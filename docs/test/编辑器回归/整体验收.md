# x2x 编辑器整体验收

从上到下执行模块，用[局部功能用例](./局部功能用例.md)逐项判断。完整回归执行全部模块，定向回归先跑入口冒烟，再跑受影响的用例及其依赖。每次回归以当次 x2x 实测为准。

## 准备环境与数据

1. 从待验收工作区各建一份私有、公开的临时生产预览。复制应用源码、配置、`public/` 和 Supabase 迁移，使用仓库安装好的依赖。在临时目录写环境配置，记录源码标识、构建方式、Node、Chrome、系统、视口和模式。macOS 上用项目安装依赖时的 Node 运行构建及测试。
2. 私有、公开各启动一个一次性本机 Supabase 实例。每套配置独立的 `project_id`、API、数据库、影子数据库及 SMTP 端口和 Docker 网络。示例私有 `project_id` 为 `x2x-editor-qa-本轮英文编号-private`，公开用不同编号或 `-public` 后缀。Auth 的站点及重定向地址指向对应预览。网络绑定 `127.0.0.1` 并在各自的网络内解析服务别名。应用全部迁移并启用 Realtime。分别填 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` 和 `SUPABASE_SECRET_KEY`，应用预览与数据库均使用回环地址。 [本地服务与迁移](../../editor/第4阶段协同部署验收.md#本地服务)
3. 私有预览设 `X2X_PUBLIC_DOCUMENTS=false`。公开预览设 `X2X_PUBLIC_DOCUMENTS=true`，仅在公开测试库开启匿名登录并配置一个邮箱已验证的专用 `admin` 文档身份。用两套独立 Chrome 上下文做访客测试。 [公开剧本库配置](../../../README.md#公开剧本库)
4. 准备所有者 A、编辑者 B、阅读者 C 和无访问权的 D 四个测试账号。以唯一批次命名数据。两位编辑者分别登录，授权测试前核对实际角色。文档入口用 `/editor`，持久化文档从列表进入 `/editor/shared/[id]`。

| 数据 | 用途 |
| --- | --- |
| 一篇空文档，页标题 `X2X-QA`，正文一空段 | 登录、新建、键入、Markdown、菜单、首字符撤销和保存回读。 |
| 一篇混合文档，包含 H1、H2、H9、普通段、两类列表、引用、格式混合段和末尾空段 | 阅读、转换、选区、编号、折叠、剪贴板及角色用例。按局部用例指定样例重建相关段落。 |
| `/editor?mode=virtual&size=500000` 与 `/editor?mode=full&size=500000` | 50 万 Unicode 码点固定样本，分别验证窗口化与全量对照。用 10 万、30 万样本补尺寸切换，用共享长文档验证真实持久化。 |
| 两篇独立共享文档与一篇旧版本文档 | 协同、切换竞态、引用权限、版本还原和撤权恢复。 |

## 执行顺序

| 顺序 | 模块与局部用例 | 通过条件 |
| --- | --- | --- |

| 2 | [长文 DOM](./局部用例/02-长文档与章节导航.md#dom-05-窗口化装卸)的 DOM-05 至 DOM-09、[文字编辑](./局部用例/03-文字编辑与剪贴板.md)、[标题与入口](./局部用例/04-标题与编辑入口.md)、[富文本](./局部用例/05-富文本与段落排版.md)、[块结构](./局部用例/06-列表引用与块结构.md) | 正文节点按视口装卸。重挂载后内容、锚点、选区和焦点可恢复。基本输入、格式、结构转换、菜单、剪贴板和历史逐项达到局部预期。 |
| 3 | [章节导航](./局部用例/02-长文档与章节导航.md#rv-03-多级目录)的 RV-03 至 RV-05、[阅读、查找与演示](./局部用例/07-阅读查找与演示.md#rv-01-阅读与编辑)的 RV 用例、[外观与输出](./局部用例/08-文档外观与输出.md) | 目录、锚点、折叠、查找替换、页宽、演示、外观与导出均可经产品入口完成。 |
| 4 | [保存与实时协同](./局部用例/09-保存与实时协同.md) | 两会话并发结果收敛，名单和光标可观察。失败与重试状态准确，断线和版本切换后云端读回符合预期。 |
| 5 | [分享与数据保护](./局部用例/10-分享权限与数据保护.md)、[评论与通知](./局部用例/11-评论提及与通知.md)、[修订与版本](./局部用例/12-修订与历史版本.md)、[会议协作](./局部用例/07-阅读查找与演示.md#co-12-演示跟随)的 CO-12 至 CO-13 | 角色与策略作用于实际操作。评论、修订、提及、通知、版本、密级及演示跟随按用例完成。 |

冒烟失败时先核对前置和环境，按原步骤复测。依赖该前置的用例记为未验证，继续独立模块。协同开始前确认两套预览的独立角色和真实 Realtime 通道可用。浏览器截断指定请求时，保留一条实际命中记录和恢复后的独立读回。

## 已有自动化

在各临时预览目录启动生产应用。以下端口为示例，两个预览分别使用自己的环境配置。

```sh
# 以下从私有预览目录执行，公开预览使用不同的网络名和端口
docker network create --opt com.docker.network.bridge.host_binding_ipv4=127.0.0.1 x2x-editor-qa-private
npx -y supabase@3.2.0 start --network-id x2x-editor-qa-private -x imgproxy,storage-api,postgres-meta,studio,edge-runtime,logflare,vector,supavisor
# 按本轮实例的状态在临时目录填入 .env.local，再构建
node node_modules/next/dist/bin/next build --webpack
node node_modules/next/dist/bin/next start -H 127.0.0.1 -p 3130
```

从仓库根目录执行。将下方环境文件路径和容器名替换为本轮私有预览的实际值。共享用例从本机私有库创建独立测试身份，公开用例使用公开预览。兼容性用例只向指定的一次性私有数据库写入自己新建的测试文档。实际打印用例在 macOS 调用系统 PDFKit，其他系统需要 `pdftotext`。

```sh
export EDITOR_TEST_URL=http://127.0.0.1:3130
export EDITOR_PUBLIC_TEST_URL=http://127.0.0.1:3131
export EDITOR_TEST_DB_CONTAINER=supabase_db_x2x-editor-qa-run01-private
private_env=/path/to/private-preview/.env.local
regression_results=$(mktemp -d)

node node_modules/vitest/vitest.mjs run tests/editor/unit

# 模块 1 入口冒烟，也可用这两个文件定向复测
node --env-file="$private_env" node_modules/@playwright/test/cli.js test \
  tests/editor/e2e/document-loading.spec.ts tests/editor/e2e/document-list.spec.ts \
  --workers=1 --retries=0 --output="$regression_results/smoke"

# 全量回归按目录发现脚本，含入口复检与性能门槛
EDITOR_BENCH=1 node --env-file="$private_env" node_modules/@playwright/test/cli.js test \
  tests/editor/e2e --workers=1 --retries=0 --reporter=json \
  --output="$regression_results/artifacts" > "$regression_results/playwright.json"
```

按[局部功能用例索引](./局部功能用例.md#需求索引)打开需求文件，使用「自动化入口」里的脚本路径定向测试。全量跑用一个 worker，回归期间避免并行跑性能或改动预览。真实 WebSocket、HTTP 回退和保存状态分别读取对应请求和界面。Chrome 的 CDP 合成输入用于验证浏览器组合事件，系统拼音和物理长按按 `QA-01`、`QA-02` 实机执行。

逐键脚本可用 `--grep ED-05`、`--grep ED-07`、`--grep ED-08` 定向执行，并按固定预期判定。历史差异复现时沿用原编号，其它偏差记为新失败。 [逐键自动化源文件](../../../tests/editor/e2e/document-markdown.spec.ts) · [模型单测源文件](../../../tests/editor/unit/document-model.test.ts) · [首轮差异报告](./验收未通过与未验证-2026-11-24.md#未通过)

## 性能与本轮结论

- 按 `QA-04` 跑生产 Chrome，固定 1280×800、禁用缓存、4 倍 CPU 降速。窗口化样本的 P95 门槛依次是首屏 1000 ms、滚动帧间隔 25 ms、键入可见更新 80 ms、目录跳转可见 150 ms。全量模式用于观察对照。样本与计时边界见[专项复核](./局部用例/13-专项复核.md#qa-04-50-万字性能)。
- 执行时用临时台账逐个勾销用例及子场景。条件满足且实际结果偏离预期记为未通过。条件缺失、跳过或证据不足记为未验证。定向复跑记录初次现象和复现情况。环境恢复后以合同相同、前置有效的复测判定。
- 新建 `验收未通过与未验证-YYYY-MM-DD.md`，使用北京时间日期。同日已有报告时追加区分本轮的后缀。按用例编号记录环境、具体操作、预期、实际或缺口、证据和最小补测方法。复测沿用原问题编号，给新问题分配未使用的编号。日期报告仅收录仍未通过与未验证的子场景。可复用的步骤和预期只维护在整体验收和对应需求文档中。
