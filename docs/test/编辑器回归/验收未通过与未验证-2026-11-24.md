## 未通过

### F-01 行内 Markdown 下划线未触发

- 用例为 [`ED-08-下划线`](./局部用例/05-富文本与段落排版.md#ed-08-行内-markdown)。在两端以编辑身份分别打开空正文段，逐键输入 `~omega~`，观察后单独按半角 Space。
- 预期为去掉两个波浪号，`omega` 应用下划线，尾部保留一个空格。
- 飞书实际正文是 `omega `，文字叶的样式含 `text-decoration: underline`。x2x 两次实测的正文仍是 `~omega~ `，编辑 DOM 未生成下划线标记。
- 影响为飞书同样的键序无法在 x2x 产生下划线。复测时使用唯一空段，分别核对按空格前、后的 DOM 和正文。 [飞书 Markdown 说明](https://www.feishu.cn/hc/zh-CN/articles/118804574721)

### F-02 粗体、斜体和删除线比飞书提前转换

- 用例为 [`ED-08-粗体`](./局部用例/05-富文本与段落排版.md#ed-08-行内-markdown)、[`ED-08-斜体`](./局部用例/05-富文本与段落排版.md#ed-08-行内-markdown)、[`ED-08-删除线`](./局部用例/05-富文本与段落排版.md#ed-08-行内-markdown)。分别在新的普通段逐键输入 `**alpha**`、`*beta*`、`~~gamma~~`，在最后一个分隔符后暂停观察，再单独按 Space。
- 预期为最后一个分隔符输入后仍保留原串和普通文本，按 Space 后才应用相应格式。
- 飞书在 Space 前分别保留完整原串，Space 后才显示样式。x2x 两次实测在输入闭合符号时就消费了标记，DOM 已出现 `STRONG`、`EM`、`S`。
- 影响为按空格之前的可见文本和键入行为不同。复测时在两个按键边界各取一次正文及格式证据。 [飞书 Markdown 说明](https://www.feishu.cn/hc/zh-CN/articles/118804574721)

**U-06 最小补测**

1. 两端各新建一篇文档，记录键入前的唯一空段和光标。
2. 用同一短间隔键入 `>`、Space、`3`，分别记录按空格、键入 `3`、一次撤销和重做后的类型、正文及光标。
3. 隔一段时间再键入 `3`，对照历史是否分为建块与输入两步。按各自条件判断，保留实际按键间隔。
