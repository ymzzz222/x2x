# 文档编辑器开发流程

状态 **第 3 阶段已启动**  
需求依据 [文档编辑器需求范围](./文档编辑器需求范围.md)  
适用场景 x2x 个人非商业使用，偶尔与少量成员协作  
资料核对日期 2026-11-20

执行顺序 **技术选型 → 长文档 DOM 装卸 → 阅读与编辑 → 协同、分享与权限 → 自动化验收 → 表格等后续功能**。每阶段同步补上相应测试，第五阶段统一做发布验收。

## 1. 技术选型与部署

### 已核对的项目现状

- 项目已经使用 Next.js 16、React 19、TypeScript 和 Tailwind，编辑器目录目前只有需求文档。现有 Markdown 组件用于历史内容阅读，仓库当前没有编辑器和自动化测试框架。[package.json](../../package.json) · [Markdown 阅读组件](../../src/app/history/_components/md.tsx)
- 现有文件传输使用 SSE 和进程内房间状态。新编辑器的正文、版本和权限由持久化服务管理，现有传输和历史阅读各自沿用原入口。[信令路由](../../src/app/api/signaling/route.ts) · [信令存储](../../src/lib/signaling-store.ts)

### 推荐组合

| 层 | 选型 | 负责的功能 |
| --- | --- | --- |
| 编辑内核 | **Tiptap 开源核心 + ProseMirror** | 文档结构、编辑事务、选区、输入法、剪贴板和插件。按需引入扩展，编辑器模块进入编辑模式时再加载。 |
| 应用交互 | **自研 React 界面 + TanStack Virtual** | 工具栏、目录、批注、权限界面和可变高度视口。虚拟列表管理正文区域的装卸，活动编辑区的 DOM 由编辑器管理。 |
| 并发合并 | **Yjs + IndexedDB** | Yjs 合并并发增量，用相对位置表示评论选区。IndexedDB 保留可恢复的本地状态与待发送队列，按账号和文档隔离。 |
| 数据与服务 | **Supabase Free** | Postgres 存正文增量、快照、评论、版本、分享和权限，Auth 管理身份，Realtime 发变更通知和在线状态。后续附件接入私有 Storage。 |
| 页面与短请求 | **Vercel Hobby** | 部署现有 Next.js 应用和短请求接口。浏览器连接 Supabase 托管的实时服务，首期无需独立 WebSocket 服务器。 |
| 自动化 | **Playwright Test + Vitest** | Playwright 跑真实浏览器、多账号、断网与回归，Vitest 跑文档规则及可独立验证的失败路径。 |

**为什么采用开源内核加自研界面。** Tiptap/ProseMirror 已有结构化编辑和 Yjs 绑定，首期可把主要工作放在长文档交互和业务规则。Lexical 是可比的开源候选，仍需验证编辑状态下的 DOM 装卸和跨窗口选区。完全自研 `contenteditable` 需要自行处理中文输入、剪贴板、撤销和浏览器差异。首期按开源扩展交付，评论、修订和分页演示由项目实现，依赖引入前逐项核对许可，Tiptap 的商业扩展单独评估。[ProseMirror](https://prosemirror.net/docs/guide/) · [Tiptap 协作](https://tiptap.dev/docs/editor/extensions/functionality/collaboration) · [Tiptap 扩展](https://tiptap.dev/docs/editor/extensions/overview) · [Lexical](https://lexical.dev/docs/intro) · [TanStack Virtual](https://tanstack.com/virtual/latest/docs/api/virtualizer)

### 开发前确定的数据边界

- **一个逻辑文档。** 正文由有顺序且有稳定 ID 的内容块组成，支持嵌套和结构版本。视口分段用于装卸和测高。先用一个 Y.Doc 作为协作状态候选，原型测量初始化时间、内存和重连补差。只有数据层实测超出预算，才评估按章节存储和同步的成本。
- **三个可独立调整的部分。** 编辑器负责内容命令与选区，视口负责加载、挂载和定位，数据层负责读取快照、提交和补拉增量。目录、搜索和锚点从同一正文状态派生。
- **内容和业务数据各有归属。** 正文增量与快照留在 Postgres，评论、修订、版本、授权、分享、通知和审计使用业务记录。评论定位带块 ID 和 Yjs 相对范围，目标被删时仍可查看评论记录及失效状态。
- **为结构升级留出兼容规则。** 固定编辑器依赖版本，读写握手检查文档结构版本。发布新节点前，用旧客户端打开新文档验证可安全只读且原内容完整。后续加表格和图片时启用受验证的新结构，避免旧编辑器清理无法识别的节点。[Tiptap 协作与结构兼容](https://tiptap.dev/docs/editor/extensions/functionality/collaboration) · [Yjs 相对位置](https://docs.yjs.dev/api/relative-positions)

## 2. 先完成长文档 DOM 滚动装卸

1. **建立可重复的样本。** 生成 10 万、30 万和 50 万字固定样本，覆盖中文、英文、emoji、长短段落、列表、多级标题以及超长单段。字符数、块数和格式密度分别记录。首屏只取必要段落和轻量索引。
2. **完成阅读视口。** 以连续块组为基本窗口，保留可见区加缓冲区，远离视口的正文节点卸载。用估算高度撑起滚动区域，挂载后用 `ResizeObserver` 校正。以块 ID 和块内偏移恢复位置，处理宽度变化、异步测高和视口上方增删。
3. **让移动和跳转共用视口。** 目录、搜索结果、锚点先定位到模型中的块，再加载、挂载和滚动，最后按交互需要设置焦点。滚动时只做窗口更新和必要预取。重索引等重活放到后台或滚动结束后，老浏览器用防抖回退。保留键盘导航和屏幕阅读器可达性。
4. **做最薄的编辑原型。** 在阅读视口内激活有界的 Tiptap 编辑片段，比较单视图整篇运行的基线与窗口化实现。由编辑器管理正在编辑的内容，中文组合输入期间固定活动范围，跨窗口选择、全选、复制、删除和撤销都以模型范围处理。测试单段超长、大段粘贴、远端在上方插入和滚出再滚回。
5. **决定是否进入全面编辑。** 阅读和编辑两条路径都满足下列预算、无选区或内容丢失时再进入阶段 3。如果仅阅读虚拟化通过，继续验证受控的多编辑片段或候选内核。若只能以章节分页编辑等方式交付，先评审该体验变化。

`content-visibility` 可用于对照渲染成本。验收用真实 DOM 挂载状态判断装卸。必要的窗口更新持续响应滚动，重任务与首屏编辑资源分批加载。[ProseMirror 视图约束](https://prosemirror.net/docs/ref/#view.EditorView) · [虚拟化和测高](https://tanstack.com/virtual/latest/docs/api/virtualizer) · [CSS 包含规范](https://www.w3.org/TR/css-contain-2/) · [Chrome CPU 降速](https://developer.chrome.com/docs/devtools/settings/throttling)

### 建议的性能门槛

用生产构建，固定浏览器版本、视口、网络和样本。CI 用固定 Chromium 环境和 CPU 降速守回归，首轮记录一台真实低配机，建议等级为旧款双核、4–8 GB 内存。以下是阶段 2 开始时的提议预算，实机校准后固化。

| 检查项 | 50 万字样本的建议目标 |
| --- | --- |
| 首屏可用 | 冷加载到首屏正文可滚动或操作，P95 ≤ 2.5 秒。分别记录冷缓存、正常在线和项目恢复后的情况。 |
| 连续滚动 | 60 Hz 环境下，固定脚本滚动帧间隔 P95 ≤ 33 毫秒。反复首尾定位后，正文 DOM 随视口窗口保持有界，已离开的普通块实际退出 DOM。 |
| 输入与定位 | 输入到可见更新 P95 ≤ 100 毫秒，已可读取的目标跨窗口跳转 P95 ≤ 300 毫秒。另记录首次远距离加载耗时。 |
| 数据正确性 | 定位、跨窗口复制、搜索替换、编辑回读及撤销结果与同一模型一致。连续滚动和装卸无持续的节点或内存增长。 |

## 3. 再完成文字文档的阅读与编辑

1. 复用已通过的长文视口，完成目录、折叠、锚点、查找替换、阅读模式、页宽以及移动端横屏。演示与正文使用同一模型，分页和连续滚动分别处理。
2. 逐步启用基础输入、剪贴板和撤销，再实现富文本、列表、引用、高亮、分割线和分栏，补块移动、块转换、工具栏、快捷键与 Markdown 输入。
3. 完成标题、图标、封面和信息显隐。每次新增节点类型都验证选区、粘贴、序列化、键盘操作和卸载重挂载。
4. 该阶段完成单人读写与回读，用与协作阶段一致的文档模型。自动保存状态在真正接入数据库持久化后验收。

## 4. 完成协同、分享与权限

共享文档已接入 Supabase Auth、Postgres 和 Realtime。采用 x2x 自建工作区和成员组，部署步骤和本地验收口径见[第 4 阶段协同部署与验收](./第4阶段协同部署验收.md)。

### 实时编辑和保存

1. 浏览器响应编辑并在 IndexedDB 持久化待提交队列，按短时间窗口合并 Yjs 二进制更新。批次携带唯一 ID、文档代次和结构版本。
2. 通过 HTTPS 提交。服务端验证身份、文档归属、当前权限、版本和批次大小，数据库事务重新核对权限并幂等追加。权限变更与写入用同一文档的权限版本协调。回执成功后展示「云端已保存」。响应丢失时同一批次可重试。
3. 数据库提交后尽力推送 Realtime 私有频道的变更提示。在线客户端按已知提交序号从授权接口补缺，重连和页面恢复时主动补拉。文档在前台时低频核对提交序号，单次通知漏收也能追平。按需生成快照并截短已纳入的增量，保留命名版本和恢复所需数据。
4. 在线成员和演示跟随位置使用临时事件，文档内容用持久化通路。Realtime 会缓存频道授权，读写接口始终核对当前权限。撤权时轮换频道权限版本，旧频道停止发送新文档提示和在线成员数据。[Yjs 增量和状态向量](https://docs.yjs.dev/api/document-updates) · [Yjs 离线](https://docs.yjs.dev/getting-started/allowing-offline-editing) · [Supabase Broadcast](https://supabase.com/docs/guides/realtime/broadcast) · [Realtime 授权](https://supabase.com/docs/guides/realtime/authorization)

### 协作功能的交付顺序

| 批次 | 工作 | 通过条件 |
| --- | --- | --- |
| 实时协作 | 两人编辑、在线状态、自动保存、断网重连和历史记录。 | 同时编辑同一段和不同段均收敛。服务重启或重试同一批次不会丢文或重复写入。 |
| 权限与分享 | 阅读、编辑、管理，评论等细分动作，邀请、链接、密码、申请、转移、继承及撤权。 | 页面、HTTP、数据库 RLS、实时加入和导出均按同一权限矩阵验收。已知链接和旧会话也受最新权限约束。 |
| 协作工作流 | `@`、评论、修订、关注通知、命名版本、还原、信息统计。 | 私有评论仅对授权成员可见。选区跟随内容变化。处理同一修订具有一致结果，历史还原后的旧连接不能重放到新代次。 |
| 管控与会议 | 密级、水印、降级审批、默认权限、权限筛查和审计。应用内演示房间支持跟随、自由浏览及重新跟随。 | 组织及角色规则在测试数据中可覆盖。共享者滚动时其他人可独立操作，重新跟随后回到共享者当前位置。 |

**必验反例。** 编辑者断网后被撤权，恢复网络时，服务端拒绝旧会话的读写，界面显示「待同步受阻」，离线改动没有写进共享文档。本机已经下载的内容无法靠远端指令即时清除。建议让原账号能够识别本机待处理状态，数据处置遵循该文档权限与设备存储设置。

## 5. 自动化验收

- **Vitest** 覆盖模型往返、块 ID、相对位置、锚点映射、裁剪窗口范围、版本兼容、权限判定和批次幂等。数据库策略和事务使用隔离的 Supabase 测试实例验证。
- **Playwright Test** 使用独立 BrowserContext 登录不同角色，核对真实页面、接口和持久化结果。每次提交运行 Chromium 的关键路径，完整回归加 Firefox 和 WebKit。使用角色和可访问名称定位、自动等待真实状态、失败保留 trace，测试后台与日常个人数据隔离。
- **性能与兼容** 用 Chromium 收集滚动、DOM、长任务和输入延迟，发布前在实际低配设备记录一轮。CDP 组合输入覆盖回归，使用真正的系统中文输入法抽验候选、取消与提交。实际 Safari 抽验独立记录。[Playwright 多账号](https://playwright.dev/docs/auth#multiple-signed-in-roles) · [多浏览器](https://playwright.dev/docs/test-projects) · [最佳实践](https://playwright.dev/docs/best-practices) · [Chromium IME](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-imeSetComposition) · [Vitest](https://vitest.dev/guide/)

| 用例 | 前置与操作 | 可判定的预期 |
| --- | --- | --- |
| E01 长文滚动与重挂载 | 用 50 万字样本反复首尾跳转，滚到远端后回到原段，在阅读与编辑模式分别运行。 | 离屏节点退出 DOM，首尾内容完整，位置可恢复，达到阶段 2 预算。 |
| E02 搜索、选区与编辑 | 跨窗口复制、替换全部、移动块并撤销，含长段落和表情。 | 搜索覆盖未挂载内容，复制范围准确，撤销恢复正确文本和格式。 |
| E03 中文组合输入 | 组合输入未提交时滚动并插入上方远端变更，再提交或取消候选。 | 光标和输入块保留，提交一次，取消零次，视口锚点稳定。 |
| E04 并发保存与重连 | 两个编辑者并发写入，断开一端网络和实时连接，模拟提交已落盘但响应丢失。 | 重新上线后内容收敛，批次只保存一次，刷新后能从数据库读回，回执前没有假保存。 |
| E05 分享、角色与撤权 | 管理员授权，阅读者打开链接，编辑者离线编辑后被撤权，再尝试旧频道、旧接口和导出。 | 每类角色只执行允许操作，撤权后的读写和同步被拒绝，旧频道收不到新文档事件。 |
| E06 评审与版本 | 另建私有评论，移动或删除其目标，逐条处理修订，创建并还原版本，旧会话随后重连。 | 评论可见性正确，定位失效有状态，还原后旧代次不能混入新正文。 |
| E07 审批与会议跟随 | 运行密级降级审批、访问和审计流程。两端加入演示房间，一端自由浏览后重新跟随。 | 审批和审计可追踪，密级策略生效，两端跟随状态与滚动位置一致。 |
| E08 阅读和编辑日常回归 | 在首、中、尾位置测试目录、折叠、页宽、演示、编辑菜单、输入格式、块操作、快捷键和回读。 | 执行结果可从正文模型和页面观察，导航和编辑行为在目标浏览器一致。 |
| E09 提及、通知和文档信息 | 成员提及其他账号、关注并编辑文档，接收方打开通知。分别用阅读者和管理者查看信息。 | 通知到达正确账号并定位，活动数据只在有权时显示。 |
| E10 后续结构兼容 | 新节点先录入测试数据，旧客户端访问、刷新和尝试写入。 | 旧客户端安全只读，受保护的新节点在数据库与新客户端中完整保留。 |

**最终放行。** 需求范围的正式验收需有逐项用例和真实运行结果。长文正确性、多人收敛、已保存数据能恢复及权限隔离都通过才发布。自动化记录构建版本、数据规模、浏览器、结果和未覆盖原因。当前文件只定义验收，待开发后生成运行证据。

## 6. 最后实现表格等扩展

- **表格仍是一项。** 先实现文档内普通表格的行列、单元格、合并、布局和滚动，再按同一需求项扩充电子表格与数据引用。按表格类型分别验证固定表头、选区和导航。
- 图片、评论附图和图片区域评论一起做。附件采用独立资源 ID，并按用户权限签发访问。代码块与公式作为独立节点。同步块引用共享内容 ID，源权限、编辑来源和循环引用在更新前检查。
- 后续画板、链接卡片、任务、表单、小组件及 AI 每次扩展一个可验收功能。新增节点前先过兼容用例，再查长文档加载、权限、旧版本和协同回归。

## 执行前确认

建议先批准阶段 2 的长文档原型和验收样本，再根据实测选定可编辑窗口实现。若实际文档规模、设备或浏览器与建议基准明显不同，先重新校准性能预算。首期会议采用应用内演示房间，外部会议系统接入有明确需求时再选。免费方案遵循各服务额度和暂停规则。
