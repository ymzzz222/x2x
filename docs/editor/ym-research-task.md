### 已确认的 DOM 口径

按 sir 最新要求，仅保存复刻所必需的真实 DOM 生成与变化信息，可用 JSON 记录关键前后状态、节点身份关系及必要 mutation。复刻验收要求块结构、必要增删改顺序、菜单、焦点和选区一致；不保存全页面 DOM、无关属性、重复子树和噪声日志。此口径替代此前“完整快照与全部原始日志留存”的约定。

“节点身份”包含同一运行会话内是否为同一 DOM 对象、页面暴露的块 ID 是否保留或变化；不同次加载的 DOM 对象不能直接判定同一。记录时可映射为稳定引用，保留复用、移动和重建关系，不要求保存随机 ID 字面值。

### DOM 标识统一规则

- 需求中的 DOM 片段、选择器、JSON 字段及节点标识，凡包含 `feishu` 的命名均统一替换为 `maiya`，包含 class、id、data 属性名称或值及相关命名前缀。例如 `feishu-ordered-list` 记录为 `maiya-ordered-list`；匹配时忽略大小写，替换结果统一为小写 `maiya`。
- 替换只作用于记录和复刻使用的 DOM 标识，不修改研究页面 DOM。浏览器定位与监控仍使用现场真实标识，导出时统一规范化，并注明已应用此规则。
- 飞书名称、真实来源 URL、用户正文和已有源码或历史文件路径保持原义，不能把来源地址改成不存在的 `maiya` 域名。
- 替换前后保持节点一一对应。若标识替换产生碰撞，记录必要映射并使用独立节点引用，不合并不同节点或省略其变化。

### 随清单提交确认的执行标准

1. 每个具体用例至少执行两次，重建相同前置状态后结果一致才记为稳定。重复的是同一入口、同一选区与同一状态，不是换入口算重复。
2. 每个已验证用例立即形成需求条目并写入所属需求文档；不等整阶段结束再回忆整理。分阶段文档可以包含多条独立、完整的需求。
3. 严格监控实际变化，落盘仅保留与需求有关的 DOM 状态、变化和规范化断言。去重不能抹掉不一致、异常、必要附加变更或失败操作；`feishu` 标识按统一规则导出为 `maiya`。
4. 每次创建、转换、删除、移动、格式修改分别验证撤销与重做；操作本身不可撤销时，记录真实历史表现及恢复方式，不能虚构撤销支持。
5. 必要 DOM、菜单、选区与保存结果必须对应同一个操作编号。截图和 AX 语义只能辅助，不能代替关键正文结构、节点身份关系和必要 mutation 证据。
6. 快捷键必须真实按键验证。菜单提示、公开说明、源码注册或控制台直接调用命令都不能替代按键结果。
7. 创建与转换通过页面点击、输入、按键、拖动实现。控制台仅用于只读查询、安装观察器、读取日志和导出证据；不调用内部编辑命令、业务 API 或直接改写正文 DOM 来制造结果。
8. 本次只确认当前环境能实测的表现。权限、协同、网络等条件不足的用例明确阻塞并请求必要条件，不绕过权限、不用推测填充、不无限重试。
9. 飞书入口不存在，须记录尝试路径及当时菜单证据，标记“不支持”或“环境不可达”；不能仅因没找到就判定不支持，更不能勾为验证通过。
10. 相同场景结果冲突时保留两份记录，固定账号、入口、选区与保存状态复测；没有可解释规则前标记“不稳定”。

12. 研究执行期间只更新本目录的文档和证据，不重构代码。最终需求说明可观察合同，不提前绑定项目技术方案。

## 4 DOM 与控制台证据规范

### 监控范围

- 首先从真实 Elements 确认正文编辑根、块容器、文本节点、列表标记、引用容器及页标题；不预先假定使用 `p`、`h1`、`ol` 或其他标签。
- 监听正文根及其子树的 `childList`、`attributes`、`characterData`，开启属性和文本旧值记录；菜单、浮层、工具栏、目录等在正文外的关联节点也须监控。
- 父节点监听用于发现编辑根替换；重载、切文档、根替换后重新核对监控就绪。iframe、Shadow DOM、虚拟化或观察盲区分别登记，不把无法访问的子树当成没有变化。
- 查询不是 MutationObserver 事件。“查”通过操作前后只读快照记录节点是否存在、属性、文本、关系、可编辑性、焦点、选区和菜单状态。
- 同一会话用观察器内部对象映射区分节点复用、移动与销毁重建，不在文档节点上写入测试属性。落盘保留必要节点引用与块 ID 变化关系，标识按 `maiya` 规则规范化。
- DOM 标记以外的编号、项目符号、折叠和高亮还需读取相关 computed style、伪元素、尺寸与可见性，只保存影响复刻的值，避免只看 `textContent` 或导出整份样式。
- 同时检查 console error、warning 和异常栈，仅保存与用例相关的异常。未发现错误只表示对应观察窗口内没有捕获到错误。

### 每次交互记录

1. 写入唯一操作编号、目标 URL、当地时间与时区、浏览器环境、窗口尺寸、缩放、输入法状态及监控会话编号。
2. 保存目标块及受影响范围的必要前置结构、父兄弟关系、菜单状态、焦点、选区、保存状态和已知历史起点；未变化的公共结构引用阶段基线。
3. 标记操作开始，逐次记录真实点击、按键、输入或拖动；中间打开菜单和修改选区也分别记录。
4. 捕获即时结果与稳定后结果。完成状态以正文、菜单和保存观测确定，超时明确记录，不用一次固定等待断言成功。
5. 导出与操作相关的必要 mutation 与事件顺序，保留节点生成、移除、移动、属性改变、文本改变的关键前后对照；按统一规则替换标识并去重。
6. 记录撤销、重做和恢复为独立操作，不与主操作揉成一个结果；复测使用新的用例运行编号。

必要 mutation 保留操作内顺序、类型和节点引用；新增或删除保留关键子树及位置，移动保留原目标父节点与顺序，属性或文本变化保留字段与旧新值。回调批次、时间和相邻节点只在解释行为必需时保存。移除节点在回调时读取关键状态，防止之后再次改写导致证据漂移；同一子树在快照与变更中通过引用复用。

MutationObserver 批次顺序不能冒充飞书内部命令或事务顺序；回调读取的新值也不一定代表每个中间状态。可观察的增删改先后应复刻，无法从 DOM 证明的内部事务不得推断。

焦点记录必要的 `activeElement` 引用；选区记录类型、方向、anchor/focus 引用与偏移、Range 和折叠状态，重复的端点不反复展开。若飞书使用隐藏输入或自绘选区，记录实际可读部分、视觉选择范围与缺口，不能用 AX 数字索引充当 DOM ID。

### 监控完整性与噪声

- 基线需包含无编辑静置、焦点切换、滚动，以及一组带监控和不带监控的相同操作，检查可见结果、焦点与操作延迟是否受影响。
- 光标闪烁、无关协同光标、重复统计更新等噪声不落盘；保存提示、菜单挂载和协同变化仅在影响本用例规则时保留。首次明确筛选规则，不能以噪声为由删掉异常或不符合预期的变化。
- 大文档或长操作分段提取受影响区域，注明监控范围、筛选依据、丢失和截断情况；有意去冗余与日志丢失必须区分。抓不到必要正文节点或变化时暂停该项验收。
- 控制台查询的对象引用会变化，关键证据须序列化为 JSON；核对其可读性、必要信息与操作编号对应关系。
- 不能安装观察器或取得必要变化时，登记“监控阻塞”，先解决能力缺口；不降级为截图验收后声称 DOM 完成。

## 5 用例矩阵与执行粒度

### 块与转换矩阵

项目目标集合 `T = {文本, H1…H9, 无序列表, 有序列表, 引用}`，共 13 项。单个转换矩阵包含 156 个有向异类型组合与 13 个同类型重复操作。标题级别不存在或入口限制时，保留对应限制单元，不用其他级别代替。

矩阵按具体入口拆分：斜杠、加号、块菜单、选区气泡、页面工具栏、快捷键、输入规则、粘贴。只对真实出现的入口执行；入口可达性本身需要证据。同一目标在不同入口的作用范围可能不同，不能直接合并结论。

### 必须展开的状态维度

| 维度 | 必须列入的具体状态 |
| --- | --- |
| 内容 | 空块、仅空格、普通文字、带行内格式、链接、中文与英文、表情及组合字符、软换行、多段 |
| 光标 | 块首、块中、块尾、文档首尾、标记旁、标题文字与编号边界 |
| 选区 | 无焦点、折叠光标、部分文本、完整文本、整块、连续多块、正向与反向、终点在下一块偏移 0、全选 |
| 结构 | 顶层、同父、跨父、嵌套子项、有后代的父项、相邻同类或异类、首尾空块、夹杂空块 |
| 属性 | 标题级别与编号、折叠、对齐、缩进、列表起点与重启、颜色、链接、批注与修订 |
| 时序 | 稳定保存后、保存中、快速连点、连续按键、输入法组合中、撤销后重做、撤销后新编辑 |
| 环境 | 编辑、修订、只读、权限降级、AI 锁、离线重连、长文档滚动、弹层失焦 |

不无理由执行所有维度的笛卡尔积，也不使用“典型场景”替代必测。创建、13 项转换矩阵、同类型操作、每个可达入口、每项显式边界分别建立子用例；交互维度至少两两覆盖，发现状态差异后展开相关组合直至规则和边界可解释。

复杂结构至少覆盖：连续同类、连续异类、标题带正文、有序与无序混合嵌套、引用含标题或列表、列表含引用、折叠标题的隐藏后代、嵌套父项仅选标题文字、跨容器选区、空块与软换行混合。结构能否创建本身是用例，不能预设合法。

每个清单编号展开为子用例，例如 `S03-C02-文本-H2-块菜单-块中-R1`；`R2` 是相同条件的重复运行。用例表保存来源、前置结构、入口、维度、状态、需求编号和证据链接，由可达性结果确定执行清单，避免漏项。

## 8 证据保存与逐步交付

各阶段开始时创建自己的目录，例如 `docs/editor/01-baseline-and-dom/`，需求文件位于 `docs/editor/01-baseline-and-dom/01-baseline-and-dom.md`；关键 DOM JSON 放在同目录的 `dom/` 下。其他阶段同样组织，不使用跨阶段共用的 `docs/editor/evidence/` 目录，也不提前生成未验证的需求内容。

每个独立结构或变化样例可保存为 `dom/<用例编号>.json`，只包含以下必要字段；没有变化或与验收无关的可选字段不保存：

| JSON 信息 | 保留内容 |
| --- | --- |
| 操作与来源 | 用例及运行编号、真实页面 URL、必要运行时间、已应用的 `feishu` → `maiya` 标识规范 |
| 前后结构 | 目标及受影响节点的必要 tag、语义属性、文本、子节点顺序，或已保存基线的引用 |
| 节点关系 | 稳定节点引用、父子关系、复用或重建关系；仅在必要时保留邻接锚点 |
| 必要变化 | 按观测顺序的生成、删除、移动、属性和文本变化，相关旧新值 |
| 交互与恢复 | 与变化有关的焦点选区、菜单保存状态、撤销重做的步骤与状态引用 |
| 异常与缺口 | 影响需求的错误、差异、监控盲区或信息缺失 |
| 必要验收参数 | 影响操作的布局、可访问性属性、响应时间与样本规模；只在对应需求涉及这些信息时保存 |

公共结构只在阶段基线保存一次，后续引用基线并记录差异；相同子树与两次一致运行共用结构数据，分别保留运行结果和证据引用。重复事件仅在不影响顺序或次数语义时压缩，必要时保留次数；创建再删除、节点移动、撤销重做、失败与不一致不能因最终状态相同而省略。

不保存整个页面 HTML、完整样式表、随机属性全集、无关控制台输出、重复快照或无必要的截图。需求文档直接引用必要 JSON，避免把大段 DOM 同时复制进 Markdown。运行矩阵放在本阶段目录，列出用例状态和需求链接；不为每次鼠标动作拆出冗余文件。

每步交付包含：本步需求文档链接、已验证数量、限制或阻塞数量、DOM 与控制台证据完整性、后续需要 sir 核对的争议项，以及下一步范围。没有被实际执行的能力明确写“未验证”。

## 9 可直接重构与投入使用的验收约定

### 需求必须交付的规则

| 合同 | 实现者必须能确定的内容 |

| 选区与命令 | 文本或整块选区、作用域、锚点解析、菜单焦点与返回、无变化与拒绝、受影响范围及后续输入位置 |

| 界面与可访问性 | 影响编辑的排版、空块占位、编号宽度、菜单热区与定位、状态样式、键盘顺序、焦点和必要 aria |

| 迁移与发布 | 旧数据样本映射、不可转换项、迁移重复执行、数据校验、失败恢复和新旧版本兼容范围 |

所有命令记录“前置条件 → 实际用户动作 → 输出结构与状态 → 继续操作或恢复”。不合法结构究竟被拒绝、降级还是拆分，必须由实测得出；不能统一写成“智能处理”。文档要明确无变化与失败的区别，以及失败前是否已有部分修改。

### 各步骤都检查的数据不变量

- 目标范围之外的文字、结构、属性和身份保持其合同；任何额外影响都须有规则或缺陷记录。
- 创建、转换、移动、格式、撤销重做不得无意丢字、重复文字或混入其他文档内容；删除与替换只能改变确认的范围。
- 编辑后的结构属于已确认合法集合，空文档仍能落光标并继续输入；必要块身份无冲突，编号与层级一致。
- 光标和选区落在有效且可操作的位置；关闭菜单、取消输入、重连或恢复后不得向过期选区继续写入。
- “已确认保存”的内容能在独立读取中恢复；本地缓存、界面 DOM 或单个保存提示都不能独自证明持久化成功。
- 本地 undo 不抹去他人的已确认编辑；切文档、模块或账户后，选区、历史、缓存、请求和协同会话不得串用。
- 权限与锁状态对所有编辑入口一致生效；生产环境是否允许写入还必须由真实服务端权限验收确认。

这些是项目可用性要求。若飞书实测违反某项，保留其证据并登记产品差异决策，不能把不变量改成“飞书如此所以可丢数据”。

### 易遗漏场景的实测方法

1. **持久化确认**：记录确认前后的操作与版本，用独立会话或隔离本地缓存的读取核对文本、层级和格式；继续编辑、保存，再读取一次，排除只读到了本地缓存。
2. **保存竞态**：连续编辑 A、B，在受控延迟与断线重连下检查最终版本；返回较晚的旧状态不能误报最新编辑已确认或覆盖 B。项目协议结果单列，飞书仅记录能观察到的现象。
3. **协同收敛**：两端记录各自操作和落点，分别等待同步稳定并独立读取；比较语义内容与结构，之后验证双方继续输入及本地 undo 的实际影响。
4. **旧数据迁移**：从真实、可授权使用的旧样本建立文字、格式、结构与业务字段对照；重复打开和重复迁移后检查无重复、无遗漏，并验证旧版本恢复和失败回退。
5. **完整工作流**：用包含目标块、嵌套、空块、格式、中文与表情的固定样例串联 J24，逐操作检查不变量；保存重开后继续做第二轮，不能只测试新文档。
6. **组合回归**：在单项稳定后执行固定、可回放的命令序列，覆盖转换顺序不同、历史回放、失败插入及远程操作穿插；按显式断言比较，失败保留最短复现序列。
7. **安全与权限**：飞书只研究正常可达交互与拒绝反馈；项目在隔离环境验证 HTML 清理、链接协议、剪贴板拒绝和真实服务端权限，不在生产研究文档中执行攻击性内容。

- 先固定环境、字体、数据规模、网络条件和监控开关，分别记录飞书基线与项目结果。必要视觉参数含字号字重、行高、块间距、列表缩进与标记、引用边线、光标占位、菜单热区和相对位置。
