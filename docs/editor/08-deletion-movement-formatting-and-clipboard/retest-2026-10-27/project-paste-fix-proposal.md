# S08 当前项目粘贴失败：定位及最小修复提案

状态：定位完成，提案待确认；没有修改业务源码。
本轮确认的工作范围是重新实测、失败定位和交付修复方案。
以下方案不构成已经实施或已经通过的修复。

## 1 可重现问题

当前实际扩展工厂、捕获监听、HTML 归一化和 PM 解析链中，
外部 HTML 的旧批注 class 被解释为本项目批注身份。
`comment-underline-S08-foreign` 生成 active/range layer。
`comment-anchor-S08-foreign` 生成 resolved/anchor layer。
各重复两轮，四次主断言均失败；正文和历史回放本身准确。
详见同目录 `project-paste-retest.json`，不是服务端越权证明。
测试使用惰性 JSDOM 和显式依赖替身，未接入生产服务或系统剪贴板。

## 2 直接原因与调用关系

`editor/index.vue:1239` 将粘贴 HTML 交给 `normalizeExternalHtmlForPaste`。
`editor/utils/externalPaste.js:1089` 是该工具的公共入口。
其内联节点克隆与序列化没有清除上述身份 class。
`extensions/annotation/schema.js:53` 的历史兼容解析器恢复旧 class 身份。
该解析器也服务历史内容，直接删除其兼容分支会损坏合法恢复。
`editor/composables/useEditorChrome.js` 另负责粘贴捕获和大小门禁。
同一归一化工具还被 AI 预览、设定和大纲等路径调用，不能无差别改变来源语义。
`looksLikeInternalMyDocHtml` 依赖可伪造的 HTML 字符串标记，不能视为身份授权。
含表格以及异常回退会提前返回原 HTML，须覆盖边界而非只修普通段。

## 3 最小方案

在真正的剪贴板入口，对传入的非可信 HTML 清除批注身份载体。
沿用现有 DOM 解析和扩展约定，不新增全局监听、store 或迁移版本。
仅清除身份相关 class/属性，保留普通文字、粗体、链接和列表结构。
覆盖旧 underline/anchor 前缀、新 comment-id 载体以及 data 身份载体。
在内部形状识别、表格分支及异常回退之前确保身份边界成立。
调用方显式选择剪贴板语义，避免改变历史恢复及可信内部插入路径。
保留 schema 的历史兼容解析器和合法批注命令。
具体改动前需核对同文档复制是否应复制批注；当前提案默认外部粘贴不恢复旧身份。
如项目要求保留同文档批注，必须先定义可验证来源，不能信任 HTML 标记。
超出这项来源裁定的协同、权限和服务端身份问题继续单列。

## 4 验收用例

两类已失败样例各两轮，期望正文保留且 foreign layers 为空。
新 class、data 载体、混合载体和嵌套载体均不得重建外来身份。
伪造 internal 标记、表格分支和解析回退不得绕过清理。
普通样式、危险标签清理、列表和现有长度门禁仍满足原断言。
Undo 恢复原结构，Redo 恢复去身份后的粘贴结果，再次 Undo 精确恢复。
合法历史 HTML 恢复仍能保留 active/resolved 批注身份。
可信内部插入的既有语义按明确来源策略分别验证。
同文档复制的批注策略经确认后增加正反例，不以便利性代替身份边界。
真实浏览器和服务端协同验收与隔离 PM 探针分开记录。
