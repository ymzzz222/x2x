# S09 历史合同、复审范围与验收入口

本文件接续[阶段记录](./09-undo-redo-and-history-boundaries.md)，不修改项目业务代码。
“新增双轮”截至 2026-10-26 指 S09 的二十一个固定条件；“复审”读取既有 Chrome 证据；“继承”沿用明确的前期合同。
前期同名需求可能重复，定位同时包含阶段路径和需求标题，不只靠编号。

## 1 历史单位的可观察定义

一个历史单位用真实一次 Undo 的内容/结构/属性输出定义，再用真实 Redo 及再次 Undo 验证。
不以命令数、mutation 数、渲染次数或 DOM ID 数推断内部事务数。
每个状态同时核对准确文字、块顺序、父子/引用关系、标记、行内格式、页标题与范围外内容。
普通 Enter 新建逻辑块；Shift+Enter 在同块新增 ace-line；两者不能只凭显示换行判等。
编号是独立非编辑标记，不混入用户正文；派生编号必须随对应历史状态恢复。
同一会话可检查原块 r/ID；新增块重做允许产生新身份，跨加载不要求 DOM 引用相等。
历史动作前的原生焦点、事件 target 和文档 Selection 分开保存；控制台采样不是原键盘目标。
历史能恢复内容不等于每个菜单和选区恢复到完全相同状态；这些差异保留在原证据。

## 6 项目验收约束

这是研究输入，不是项目实现已经通过的结论。
项目必须保护文档/模块身份、正文之外的标题、范围外内容，以及已经确认保存的用户数据。
本地历史不能撤销远端已确认内容；切文档与卸载后不能继续向旧选区或旧会话写入。
可逆编辑须有完整中间状态与有效落点；复制/取消/禁用反馈不能意外清掉旧 redo。
项目现有 S08 七项保护合同、剪贴板/HTML 边界和内容长度策略不被飞书例外覆盖。
按钮、快捷键、beforeinput、菜单输入框、阅读/锁及保存中等入口须在真实项目环境分别验收。
版本还原必须有独立确认和可识别目标版本，后续新编辑、保存和历史边界不能沿用过期栈。
迁移、协同冲突、断线重连、账号权限和版本恢复并发属于 S10/项目专项，当前报告不宣称通过。
