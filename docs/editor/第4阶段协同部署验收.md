# 第 4 阶段协同部署与验收

文档列表入口为 `/editor`，共享文档入口为 `/editor/shared`。长文样本入口（如 `/editor?size=500000`）用于窗口化性能与单人编辑回归。共享文档可从空白或 10 万、30 万、50 万字样本创建，拥有独立文档 ID 和云端内容。

## 实施与飞书对照

| 需求 | x2x 行为 |
| --- | --- |
| 实时协同与离线保存 | 浏览器使用同一份服务端 Yjs 初始快照。编辑批次进入按账号和文档隔离的 IndexedDB，HTTPS 获得幂等回执后显示「云端已保存」。数据库提交后发私有 Realtime 通知，客户端按序补拉并在前台定期核对。 |
| 分享与权限 | 管理者按已验证邮箱授权阅读、编辑或管理。链接可设置密码并停用。已登录成员可申请访问，所有者可转移所有权。工作区、成员组和部门由 x2x 管理，部门下属组可继承父组文档授权。直接授予或撤回的角色优先于继承或链接。 |
| 评论、修订与通知 | 评论支持全文、选区和块定位，私有评论由发起人和指定成员可见。支持回复、表情、解决、恢复、评论链接与文档点赞。修订记录替换前后的文字，接受前检查原文和文档代次，接受与正文写入在同一事务。正文提及在云端保存确认后通知有权限的账号。 |
| 版本 | 按作者和时间显示最近保存，支持命名版本、正文比较、复制版本链接和还原。历史版本只读。还原会备份当前内容、切换代次并保留旧代次本地待提交数据。每次自动保存记录展示提交信息，独立可还原快照以命名版本为单位。 |
| 密级和审计 | 可设置普通、内部、受限密级及访问者水印。降低密级由所有者审批。阅读者和编辑者分别配置评论、复制、打印、下载、创建副本。下载与副本由服务端复核，复制和打印由编辑器入口执行策略。工作区管理者可筛查自己有管理权的多篇文档的有效权限。 |
| 演示协作 | 分享者启动应用内演示房间，参与者可跟随、自由浏览和重新跟随。标注绑定共享文档的位置。演示面板可显示或隐藏有权阅读的评论。 |

参考[飞书功能与权限范围](./文档编辑器需求范围.md)、[保存和历史状态合同](./11-reconstruction-acceptance/11-state-and-service-contracts.md)及[开发流程](./文档编辑器开发流程.md)。表格、图片、代码块与同步块继续按第 6 阶段安排。

## 本地服务

使用运行中的 Docker 和 Node.js 22 或更高版本。从项目根目录启动只绑定本机的 Supabase 网络。首次启动会依次应用 supabase/migrations。

```sh
docker network create --opt com.docker.network.bridge.host_binding_ipv4=127.0.0.1 x2x-editor-local
npx -y supabase@3.2.0 start --network-id x2x-editor-local -x imgproxy,storage-api,postgres-meta,studio,edge-runtime,logflare,vector,supavisor
```

本机使用 CLI 的 API URL、Publishable Key 和 Secret Key 填写 .env.local。远端使用对应项目的三项配置。应用只在服务端读取 SUPABASE_SECRET_KEY，另两项用于浏览器连接和登录。

本地配置仅用于隔离开发，账号注册完成即可登录。云端项目需启用邮箱校验、配置站点地址及登录重定向，并将三项变量配置到对应服务。CLI 的迁移须指向明确的测试项目或授权环境。共享页在服务端核对邮箱已验证。PostgREST 的写入 RPC 只允许服务端角色执行。就绪后从两个独立浏览器会话登录验证。[Supabase 本地开发](https://supabase.com/docs/guides/local-development) · [Supabase Realtime 授权](https://supabase.com/docs/guides/realtime/authorization)

## 可复跑验收

运行 Next.js 生产预览后，在仓库根目录执行。EDITOR_TEST_URL 指向预览地址。共享用例使用本地专用 Supabase 实例并创建隔离测试账号，需要真实 Chrome。

```sh
node node_modules/vitest/vitest.mjs run tests/editor/unit/document-model.test.ts
EDITOR_BENCH=1 EDITOR_TEST_URL=http://127.0.0.1:3106 node node_modules/@playwright/test/cli.js test tests/editor/e2e --workers=1
```

## 边界

正文保存状态以服务端回执为准。连接断开后可以在已打开页面继续编辑，复连前待提交改动保存在本机。权限变化后新的读取和写入按当前角色判断，已下载的正文仍可能留在客户端。复制和打印策略作用于产品入口。

本文档记录本地 Supabase 验收和部署配置。云端部署、真实系统输入法及浏览器兼容需要在对应环境验收。
